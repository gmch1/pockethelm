# App 返回前台与冷启动恢复

状态：已发布（0.4.4 / versionCode 14；随 0.4.7 变更统一提交）

## 需求与验收

- 切后台再回来不反复断开重连；进程被回收后恢复上次引擎、页面、当前会话和近期内容。
- 先显示本地内容，再更新服务器事实；缓存不赋予在线状态、不恢复运行控制信息、不自动重发消息。
- 短暂后台保留连接，停止主动轮询；超过宽限期释放连接。不引入常驻服务或通知。
- 缓存使用 Android Keystore 加密、限制体积、按开发机隔离；切换配对不串数据，损坏缓存不影响连接。
- Codex 列表不等待逐会话状态查询才出现，当前会话优先同步；已删除 ZCode 会话不因缓存重新出现。
- 验证两种引擎恢复、后台宽限与断线、缓存损坏/隔离、发送保护及真机冷启动/切后台。

## 根因

- 两个 ViewModel 的 background() 都立即断开 SSH；每次 onStart 重走连接与多项初始化。
- 列表、选中会话、时间线仅在内存，进程重建后为空；引擎仅 rememberSaveable，完整冷启动仍默认 Codex。
- Codex loadSessions 等待最多 30 次逐会话 turns/list 后才发布列表，并阻塞当前会话读取。

## 实现与验证

- 两个 ViewModel 使用 30 秒后台宽限，离开前台停止主动轮询；短暂返回复用连接，长期后台释放连接，返回时先刷新当前会话。手动断开与真实通道中断仍立即进入断线/待确认处理。
- 新增 `ResumeCache.kt`：按引擎保存一份 Android Keystore AES-GCM 加密快照，存放 noBackupFilesDir；上限 2 MiB、有效期 7 天，最多 80 条近期时间线，单条/总文本预算限制并标注截断。读取与写入均在 IO dispatcher，连续流式响应合并写入；后台时另存一次当前快照。
- 缓存归属包含 SSH 身份、配对 environmentId 和项目根目录；不匹配或损坏时忽略，不阻碍连接。只恢复列表、页面、当前会话、近期内容及原计划选择/校验 guard，不恢复在线状态、执行 ID、队列、额度或已确认模型设置；草稿与待确认命令沿用已有加密存储，绝不自动重发。
- 冷启动恢复上次引擎和选中会话；显示“上次内容/状态待刷新”，联网后替换为服务端事实。ZCode 完整列表确认缓存会话已移除时清除其显示；不迁移旧会话。
- Codex 列表在 thread/list 返回后立即发布，状态查询限并发后续补充；相同活动时间/运行态复用已知状态，过期连接、列表请求或 turn 事件之后返回的旧结果不能覆盖新状态。
- Compose 保存引擎/页面切换中的列表与聊天 UI 状态，去掉列表重新进入时无条件滚到顶部的行为；ZCode 列表滚动状态移到聊天分支外保存。没有新增后台服务、通知或依赖。
- Release JVM：75 项，74 通过、1 项真实 SSH fixture 缺失跳过；lint 与构建通过。最终 0.4.4 / versionCode 14 APK 在既有 Xiaomi 真机覆盖安装，整组 instrumentation 39/39 通过，其中 8 项新用例覆盖两种引擎冷恢复、连接宽限、加密/损坏/隔离、列表先展示后补状态、删除缓存会话；原发送/回执/历史恢复和阅读 UI 用例也通过。
- 首轮回归中，旧 ZCode 断线用例使用 leave() 代指立即断线，与新宽限策略不符；改为直接模拟真实 disconnect，保留原断线后 UNCERTAIN/待确认断言。首轮失败日志留存，不算通过；最终以 `instrument.txt` 的 39/39 为准。
