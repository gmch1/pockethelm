# 列表页顶部区域冗余整理

状态：已发布 0.4.8 / 18（2026-11-02），Review、真机验证与公开下载校验完成

## 需求与验收（草案，由 Codex 维护）

- 用户反馈：列表页顶部「开发机 / 会话 / 开发机 已连接 / Codex·ZCode」层层堆叠，信息重复（所谓「重叠」）、占屏过大且基本无用，希望收敛。
- 目标：竖屏列表页在首屏内尽量早地出现第一条会话；顶部只保留有信息量或有操作价值的元素；同一信息全页只出现一次。
- 验收条件（草案）：
  1. 竖屏非紧凑高度下，列表页顶部固定区域（含引擎切换与标题栏）合计不超过约 150dp，或较现状减少一半以上。
  2. 开发机名称、连接状态在全页各出现至多一次；离线/错误仍由现有错误条覆盖，无信息丢失。
  3. 引擎切换、刷新、搜索、项目筛选、添加项目、进入连接页的入口全部保留（可换位置/形态）；聊天页与紧凑高度布局不回退。
  4. 真机验证竖屏/横屏/键盘弹出三种状态的首屏内容占比与操作可达性。

## 现状盘点（竖屏、非紧凑高度 ≥480dp，ZCode 会话页自上而下）

| 层 | 内容 | 高度约 | 来源 |
| --- | --- | --- | --- |

| 2 | 顶栏：副标题=开发机名 + 26sp 大标题「会话」+ 刷新 | 66dp | `WorkspaceUi.kt:48-57`（subtitle 传入 `profile.name`，见 `ZcodeScreen.kt:50,61`） |

| 4 | 搜索输入框（整行常驻） | 68dp | `WorkspaceUi.kt:111-116` |

合计约 **320dp**；典型手机可用高度约 780dp，**首条会话之前约四成屏幕是固定装饰**。

重复信息映射（用户所说「重叠」的实体）：

- 开发机名（`profile.name`）出现 **2 次**：顶栏副标题（层 2）与开发机卡片（层 3）相邻展示同一字符串。
- 连接状态出现 **2 次**：卡片「已连接」（层 3）与计数行「正在同步/离线缓存」（层 6）；断线时错误条还会再报一次。
- 页面标识出现 **2 次**：26sp 大标题「会话」（层 2）与底部 NavigationBar 选中项（`WorkspaceUi.kt:59-68`）。
- 开发机卡片的唯一操作是跳连接页（`ZcodeScreen.kt:59` `connection = { tab = 2 }`），底部导航已有同一入口——整张卡片信息与操作均冗余。
- 引擎切换为低频操作，却常驻整行（60dp）。

## 整理方案（建议，供 Codex 选型）

**方案 A（激进收敛，推荐）**

- 顶栏：去掉列表页副标题（开发机名只在连接页展示）；标题降为普通单行（约 18sp）或直接沿用底部导航指示、仅在聊天页保留会话标题。
- 删除开发机卡片：正向「已连接」状态并入计数行一行文案；离线提示沿用错误条与「离线缓存」标注；入口用底部导航。
- 搜索改为图标展开（紧凑高度已有该形态 `WorkspaceUi.kt:126`，直接复用到全高度）。
- 引擎切换移出常驻行：放入连接页顶部或顶栏 overflow 菜单（保留 rememberSaveable 语义即可，切换逻辑 `EngineApp` 不动）。
- 预期：固定区域降到约 90-110dp，首条会话进入首屏上部。

**方案 B（保守收敛）**

- 保留引擎切换行与常驻搜索；仅合并「副标题+卡片」为顶栏单行小字（如「开发机名 · 已连接」），删卡片；标题降到 18sp。
- 预期：固定区域约 260dp（较现状省约 60dp），改动面小，回归风险低。

两方案均不动聊天页（ChatRunHeader/设置条）与底部导航；紧凑高度（<480dp）现有隐藏逻辑保持。三方案对照原型见 `.local/prototypes/`（仓库外忽略目录）：`list-top-chrome-compare.png`（三方案并排静态对比图）、`list-top-chrome-compare.html`（浏览器打开的交互版）、`list-top-chrome.html`（可视化片段源文件），每屏含各层高度标尺与「首条会话」位置标记；方案 A 固定区域实测约 90dp（50dp 顶栏 + 44dp 上下文行）。

## 待决策问题（Codex）

2. 引擎切换最终归宿：连接页、顶栏菜单、还是保留常驻但缩高（`small=true` 已支持 12sp 标签）。
3. 「已连接」正向状态是否保留任何常驻展示，还是只在离线/错误时出现（与 0.4.4 恢复缓存「离线 · 缓存」语义合并）。
4. 大标题「会话/任务中心」是否保留（涉及 `WorkspaceScaffold` 的 chat/非 chat 两种标题模式与既有界面测试断言）。

## Codex 设计提案：两行顶部（2026-11-01）

用户认为原三方案图不理想，要求 Codex 重新设计。本轮交付静态对比图与可交互的独立 HTML，保留此前原型，不修改或发布 Android App。

### 设计取舍

- 沿用现有绿色与中性色，不采用前一张原型的紫色；底栏继续只显示图标，保留可访问名称和明确的绿色选中态。
- 顶部第一行 56dp：Codex / ZCode 直接切换 + 搜索 + 紧凑的新建按钮。没有证据将引擎切换认定为低频，本提案保留一键切换，不单独占一整行。
- 第二行 48dp：当前项目选择 + 会话数 + 列表菜单。刷新、最近/较早活动排序、只看执行中放在列表菜单。
- 默认列表按最近活动跨项目平铺。每行第一行标题，第二行项目、状态和时间；取消重复的项目大标题与完整路径。运行中使用轻微背景与绿色标识；等待/失败保留文字及区别色。
- 项目选择打开底部面板，列出项目和路径，以区别同名目录；“添加项目”位于面板末尾。新建入口先选目标项目，保留现有目录选择能力。
- 搜索替换顶栏内容；项目筛选继续生效，支持无结果状态和清空。原型会独立保存两引擎的筛选与排序条件。
- 正常连接不占独立卡片，开发机详情由底部连接入口查看。离线只在顶部显示一条提示和重连入口，各行仅保留标题、项目、时间，隐藏实时运行标记，也不重复添加“上次内容”标签。
- 主要按钮触控区域维持 48dp，视觉图标约 20–22dp。大字体示例允许标题两行，列表自然滚动；不依靠缩小正文来增加首屏内容。
