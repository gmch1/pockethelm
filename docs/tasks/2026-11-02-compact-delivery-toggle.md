# 紧凑的排队 / 插入切换按钮

状态：已发布 0.4.9 / 19，Review、真机验证及商店下载校验完成

## 需求与验收

- 用户反馈双选项并排展示过高、过宽，要求只展示当前模式，点击直接切换。
- 两引擎共用同一个发送模式按钮；显示“排队”或“插入”，点击切换到另一模式，不使用下拉菜单。
- 输入中切换不得收起键盘、移动焦点、丢失选区或草稿，也不得触发发送。
- 缩小可见控件和输入区域留白，仍保留至少 48dp 的触控高度及可访问操作名称。
- 沿用本轮更新商店的授权，Codex 直接实现、验证和发布，不委派其他 AI。

## 实现与验证

- `WorkspaceUi.kt`：用单个按钮替换双项 Tab；视觉约 64 × 28dp，触控 64 × 48dp；中性背景配文字和小切换图标。
- 输入栏去掉内部上下 4dp 留白，外部上下留白从 6dp 减为 4dp；模式区域宽度从 112dp 减为 64dp，给输入文字留出更多空间。
- 按钮不获取编辑焦点，固定组件位置，仅变更当前模式；通过状态描述和“切换为…”操作名提供可访问语义。
- 更新原有真机回归：实际触摸连续四次切换，逐次检查键盘、焦点、选区、草稿及输入框位置，断言只显示当前模式、没有发送；另检查两引擎的草稿和模式独立性。
- 本轮只涉及共用输入栏、对应测试与版本配置；保留之前未提交的列表改动，不改发送协议。
- 私有验证材料：`~/.local/state/pockethelm/composer-toggle-20261102/`。

## Review

- 单按钮通过 `changeInsert(!insert)` 复用既有模式映射，Codex 与 ZCode 的插入/排队协议保持原样。
- 按钮和 TextField 不随模式切换创建新的页面或弹窗；触控范围与可见高度分离。
- 整体结论：review 通过。
